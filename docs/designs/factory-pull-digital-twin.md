## Vision

### 10x Check
A digital twin that visualizes material flow and bottlenecks across 3 floors of manufacturing, a 2nd-floor conveyor bridge, and a 4-floor ASRS warehouse under a pull system. The 10-star feature includes "X-Ray Flow-Pulse & Interactive Time-Traveler" rendering semi-transparent floors with velocity-colored glowing particle flows and a timeline allowing full play/pause playback and instant time-travel scrubs to diagnose exactly when and how bottlenecks develop.

- **Simulation Engine**: Utilizes a client-side procedural simulation engine. To support instant timeline scrubbing, the simulation is pre-calculated from tick 0 to 100 and cached in memory whenever the shock configuration changes, enabling O(1) state lookup at render time.
- **Pull System & Flow Logic**: Material flows from MFG Floor 3 down to Floor 1 via vertical lifts/chutes, then across the 2nd-floor conveyor bridge to ASRS Floor 2, and up to ASRS Floor 4. Replenishment pull signals propagate backward in reverse. ASRS Floor 4 consumes items at a default rate (e.g. 1 unit every 3 ticks) to drive the pull system. Buffers exceeding 5 units are highlighted dynamically as bottleneck nodes.
- **Shock Events**: Users can inject manual shocks (e.g. machine breakdown at Floor 2) directly from the viewport controls. Shocks are toggled active/inactive and stored in the configuration as a list of active shocks. Shocks halt downstream flow and cause upstream queues to swell, demonstrating backpressure and starvation.

## Technical Implementation Details
- **Visuals & Rendering**: Built using React Three Fiber, Drei, and Three.js. Semi-transparent floor plates use `transparent: true` and `depthWrite: false` with the lowest `renderOrder` (e.g., 0). Conveyor belts and lift shafts use a medium `renderOrder` (e.g., 1). Glowing particles use the highest `renderOrder` (e.g., 2) to guarantee they render cleanly on top of transparent floors without WebGL depth-sorting glitches.
- **Particle Flow**: Pre-allocated `InstancedMesh` with a max capacity of 500 particles is managed via refs inside R3F's `useFrame` loop to bypass React reconciliation overhead. Particle positions are lerped between ticks to eliminate jitter.

## Reviewer Concerns
The spec review from the adversarial reviewer returned a quality score of 6/10, raising the following issues that should be addressed during implementation:
1. **Shock Temporal Behavior**: It needs to be clarified whether shocks apply globally (active for all ticks) or have specific start/end ticks on the timeline.
2. **Buffer Capacities & Backpressure Rules**: The simulation should specify maximum buffer sizes (e.g. capacity of 10) and define how upstream blocking/halting behaves when a queue overflows.
3. **Timeline Boundary Behavior**: Define what happens when playback reaches tick 100 (e.g. looping back to 0 or pausing).
4. **Spatial Layout & Coordinates**: Need exact Three.js coordinate positions for the stacked MFG floors, the 2nd-floor conveyor bridge, and the 4 ASRS warehouse floors to prevent guess-work layout code.
5. **Pull Logic Mathematical Formulation**: Define propagation speed (instantaneous vs. tick-by-tick) and trigger thresholds (e.g. request triggered when buffer falls below 3).
6. **Particle Paths Link Network**: Map out nodes and link arrays along which particles will lerp.
7. **WebGL Sorting with Transparent Floors**: Standard `depthWrite: false` might cause conveyors/particles to bleed through floors in front of them. Suggested mitigation is to keep floor plates opaque with semi-transparent wireframe overlays or implement a strict bottom-to-top `renderOrder` hierarchy.
